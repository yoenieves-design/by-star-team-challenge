# Delivery roadmap

## Phase 1 — available in this branch

- Shared responsive application shell and eight shortcode pages.
- Fictional daily log, history, sleep trend, review queue and follow-up tracking.
- Profile, daily checklist, JSON export and print summary.
- Environment integration placeholder with explicit missing readings.
- Reproducible build, model tests and continuous-integration checks.

## Phase 2 — WordPress integration

Create pages, install the generated snippet, check theme compatibility, choose final branding,
and rehearse the demo. Confirm challenge rules, submission deadline, sources and judging criteria.

## Phase 3 — persistence and evidence

Define identities and access roles, add authenticated server storage, formalize the observation
schema and migration strategy, and document scientific sources for any future assessment logic.
Add individual baselines only when enough observations and a defensible method are available.

## Phase 4 — integrations and autonomy

Select actual sensors/data sources, implement provenance and quality checks, determine whether
Workers adds value, and design offline page availability and synchronization with explicit conflicts.

## Demonstration script

1. Load the fictional week from Profile & mission.
2. Open My status: identify the two illustrative review items.
3. Inspect sleep history in Indicators.
4. Open Alerts & actions, read the explanation, and record follow-up.
5. Add or edit today's log; verify the dashboard changes.
6. Export the fictional report.

The product claim is: collect observations, make changes understandable, and support follow-up.
